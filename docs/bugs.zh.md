# 缺陷库 · 公开版

[中文](bugs.zh.md) · [English](bugs.en.md)

英文版视频生产线上踩过的坑，按「动效与排版 / 导出与帧 / 英化与草稿」分组。
每条写四件事：现象、根因、修法、判据。编号沿用内部账本，缺口是未公开的条目。

> 这些条目全部来自真实交付。删掉了本机路径和文件清单，保留了判定方法——判据比结论有用。

## 动效与排版（DB-01 ~ DB-30）

### DB-01 · `.pad` 盖住先写进去的标签：绝对定位兄弟的前后由 DOM 顺序定

**现象**：版面页每格缩略图右上角要放"启用 / 不用"角标，HTML 写成
`<div class="th"><span class="off">不用</span><div class="pad">…缩略图…</div></div>`，
`span` 先写、`pad` 后写。结果**角标一个都看不见**，样式全对（`position:absolute; right:12; top:12`）。

**根因**：`.pad` 是 `position:absolute; inset:14px`，**也建立了定位上下文并覆盖整块**；
两者同在 `.th` 里，`.pad` 在 DOM 后面 ⇒ 画在上面，把标签**盖住**了。
不是"没渲染"，是"被不透明的兄弟压住了"。

**修法**：给标签 `z-index:6`。
⇒ 通则：**同层绝对定位的兄弟，前后顺序由 DOM 决定，`z-index` 只在需要越过时才用**。
　 写完先问一句"它后面有没有另一个 absolute 会盖上来"。
⇒ 变红判据：截图里 `document.elementFromPoint(角标中心)` 返回的不是角标本身 = 被盖住了。

### DB-02 · `aspect-ratio` 按宽度算高度，会在定高容器里撑破

**现象**：组件页 12 格里放"视频位"，CSS 写 `width:100%; aspect-ratio:16/9`。
格子宽约 400、`demo` 区高只有约 150 ⇒ 高度算成 225，**16:9 框直接顶出格子、压到页脚**。

**根因**：`aspect-ratio` 的"另一条边"是按**可用宽度**推的，容器高度不参与计算。
在"高固定、宽弹性"的格子里用它 = 让内容决定高度，必然溢出。

**修法**：定高容器里放比例盒子，**两边都写死**（208×117）。
⇒ 通则：**`aspect-ratio` 只适合"宽度自由、高度跟着走"的容器**（如满宽的视频位）；
　 一旦父容器高度是固定的（网格格子、卡片插槽），必须显式给宽高。

### DB-03 · `--line` 压在 `--void` 上等于隐形：结构线也要按"能不能看见"选色

**现象**：六图页的"雷达 → AND → 触发呼叫"汇合线，用 `stroke="var(--line)"`（`#2C323C`）。
页面上**一条线都看不到**，第一反应是"SVG 没画出来"，去查 DOM、查 path、查 stroke-width，查了半小时。

**根因**：`--line` `#2C323C` 与 `--void` `#14171C` 的对比只有约 **1.5:1**，1px 宽在深底上肉眼不可辨。
**它画了，只是看不见。**

**修法**：示意图内的连接线升到 `var(--dim)`（`#8D96A3`，对比约 5:1）。
⇒ 通则：**"结构线"这个词是按用途分的，不是按亮度分的。**
　 用在"分割两个面"时 `--line` 合适（两侧都有底色）；
　 用在"深底上单独一根线"时必须换更亮的一档。
⇒ 变红判据：把图缩到 25% 看一眼，**线还在吗**？不在就是对比不够，不是没画。

### DB-04 · `.k` 撞车：浅色面板上一切正常，深卡上全变白胶囊

**现象**：看板页"设备状态"深卡里，四行键名（Wi-Fi 信号 / PSRAM 占用 / 芯片温度 / 当前码率）
变成了**四个白色圆角胶囊**，把文字盖住。而同一份 HTML 上方"实时读数"面板（浅色）看起来完全正常。

**根因**：KPI 卡片的类名是 `.k`（带 `background:var(--glass-bg)`、`box-shadow`、`border-radius:20px`），
面板行的键名也叫 `.k`。规则 `.k{...}` 对两者同时生效 ⇒ 每个键名都被包成一张玻璃卡。

**为什么藏得住**：实时读数面板本身就是白玻璃，白底 + 白卡 = **看不出多了一层**。
一放到 `#002CCD` 深卡上，白卡立刻显形。

**修法**：KPI 卡片改名 `.kpi`。
⇒ 通则：**类名不要用单字母**。`.k` / `.v` / `.t` 这种在同一个项目里一定会被复用第二次。
⇒ 判据：**把该页放到最深的那块底上看一眼** —— 深底是"多余背景"的显影剂。

### DB-05 · `.chip` 撞车：组件库的胶囊名不能拿来当色块

**现象**：元素页八个色块本应是满宽方块（`height:96px`），实际渲染成 **36px 宽的竖条**。

**根因**：色块类名 `.chip`，而 kit 的基础样式里 `.chip` 是**胶囊组件**：
`display:inline-flex; padding:0 18px; border-radius:999px`。
`.sw .chip{height:96px}` 只覆盖了高度，**宽度被 `inline-flex` 收成内容宽**（空 div 只剩 padding 36px）。

**修法**：色块改名 `.blk`，并给 `box-shadow:inset 0 0 0 1px var(--hair)` 让近白色块有内描边。
⇒ 通则：**局部元素不要复用 kit 的语义类名**（`.chip` / `.card` / `.tag` / `.badge`）。
　 要用就先确认那个类有没有 `display` / `padding` / `width` 这类会改变盒子模型的声明。
⇒ 判据：**给元素一个明确的 `width` 再截图** —— 如果宽度不听话，就是 `display` 被别人的类抢了。

### DB-06 · 相机关键帧：一个时刻不能既是「上一段终点」又是「下一段硬切起点」

**现象**：19 镜里"推近 P4"那一镜从头到尾没推起来，整段停在远景。`camAt` 逻辑没错，缩放值也没错。

**根因**：`CAM` 表里 `1.78s` 被写成两条意图 —— 既是"0→1.15→1.78 推近到 0.94 的终点"，
又是"1.78 硬切到 CSI 1.02 的起点"。而 `camAt` 取**最后一条 `t <= t` 的关键帧**，
于是 1.78 之后取到的永远是"CSI 起点"，并从它一路插值到 3.90 —— 推近的那条被跳过。

**修法**：拆成 `1.775`（终点）+ `1.78`（`cut:1` 起点）。
⇒ 通则：**关键帧表里 `cut` 是"区间起点"的属性，不能和"区间终点"共用一个时刻**；
　 要给硬切留 1 帧（1/30s）的缝，或者干脆用两套表（段表 + 段内相机）。

### DB-07 · `ease` 属于区间起点那一帧 —— 写在终点等于没写

**现象**：给推近配了 `snapo`（冲+修正），实测仍是最普通的 `eio`，前 0.3 秒几乎不动。

**根因**：`camAt` 里 `const e = (a.e || eio)(p)` —— **`a` 是区间起点**。
我把 `e: snapo` 写在终点那条关键帧上，起点没有 `e` ⇒ 走默认 `eio`。
**参数在文件里，但从来没被读到**，零报错。

**修法**：所有 `e` 移到起点帧。
⇒ 通则：**凡"区间属性"（ease / 时长 / 方向），一律写在起点**。
　 判据：把 ease 换成极端的 `lo` / `xi`，画面节奏**必须肉眼可辨**；
　 换完没差 = 属性没生效。

### DB-08 · HUD 容器没设 `id`，九个 CSS 选择器全部落空 ⇒ 元素建了、就是不显示

**现象**：帧格、压缩条、封包、音频节点、浏览器窗、局域网圈、划叉、管线 —— 八个模块一个都不显示。
`document.querySelectorAll('#hud2 > *').length` = 13，元素都在，`opacity` 有 1 的，但画面空白。

**根因**：CSS 写的是 `#grid15 .cell`、`#aud .node`、`#web .win`…（**id 后代选择器**），
JS 建元素时只给了 `class`：`mk('div','el',...)`，**从头到尾没设 id**
⇒ 选择器一个都不匹配 ⇒ 子元素没有 `position:absolute`、没有背景、没有尺寸，堆在一起看不见。

**为什么难发现**：容器本身有 `opacity`（JS 设的），`getComputedStyle` 读得到；
子元素全在但"没样式"，视觉上就是一片空白，**控制台干净**。

**修法**：`bits.id='bits'; g15.id='grid15'; …` 九个补齐。
⇒ 通则：**CSS 用 id 选择器，JS 建元素就必须显式给 id**；
　 混用 id/class 时，判据是 `document.getElementById('grid15')` 不能是 null，
　 或者干脆全用 class（`mk(tag, cls)` 只给 class 时，CSS 就别写 `#id`）。

### DB-09 · 同一个注释锚点在 CSS 和 JS 里各有一处，`replace` 插错了地方

**现象**：给术语条加样式 + 加驱动代码，改完页面直接白屏，报
`SyntaxError: Private field '#term' must be declared in an enclosing class`。

**根因**：两处都写了 `/* 播放条 */` —— 一处在 `<style>`，一处在 `render()` 里。
第一次 `replace("/* 播放条 */", ...)` 意图改 CSS，但 `indexOf` 命中的是**文档里第一个**，
恰好在 `render()` 附近 ⇒ 整块 CSS 被插进了 JS 字符串里。

**修法**：从 JS 里删掉误插段，改成在 render 里写驱动逻辑。
⇒ 通则：**别用"注释文字"当替换锚点**。锚点要么带上下文（前后各一行代码），
　 要么用行号 / 函数名定位。同一句话在样式和脚本里很容易重名。

### DB-10 · 判据阈值必须跟着底色走：浅底上「亮于 90 的占比」恒等于 100%

**现象**：末帧判据 `亮于 90 的像素占比应在 2%–40%`，实测 **84%**，报 FAIL。

**根因**：这条判据是从 20-风洞（**深底** `#14171C`）抄来的 —— 深底上"亮"= 主体在场。
本套是**浅底** `#EFF6FF`（亮度约 244），**整屏天然全亮** ⇒ 判据恒真/恒假，量的是背景不是主体。

**修法**：换成**暗像素占比**（板子是黑的）：`6% < (lum<60).mean() < 55%`。
⇒ 通则：**判据里的绝对阈值（亮度 / 面积 / 对比度）都带底色前提**，换底色必须重标；
　 迁移判据时先问一句"这条阈值是相对什么量的"。

### DB-11 · 浅底片的「密度」不能只用 ink 量：白玻璃在指标里等于不存在

**现象**：给 S08 补了 10 组矢量元素（图纸底 / 尺寸线 / 引线 / 像素块 / 波形 / 读数），
肉眼看满了不少，但 `ink`（偏离底色 >48 的像素占比）只从 **4.1% → 5.3%**，几乎没动。

**根因**：这套底色是 `#EFF6FF`，玻璃卡是白 `.96→.82` 渐变 —— 白压浅蓝，**diff 只有 17**，
过不了 >48 阈值。⇒ 整张卡在指标里等于不存在；同理 1px 细线（`stroke-opacity .11`）也不过阈值。

**修法**：浅底片判密度用 **edge**（一阶差 >12 的像素 ‰，对细线敏感）作为主指标。
同一组帧：edge **11.2‰ → 40.2‰（3.6×）**，这才是"矢量元素变多"的正面证据。
⇒ 通则：**ink 适合深底/实心块，edge 适合浅底/细线；两者不可互相替代，报数时两个都给。**

### DB-12 · `.fbox` 自带 z-index:2 ⇒ 后加的全屏矢量层画在它下面，且零报错

**现象**：往 S08 的 `#world` 末尾插了一张全屏 `<svg id="vecF">`（DOM 顺序在画幅之后），
里面画的卡片、引线**全都不显示**；`opacity` 查出来是 1，`getBoundingClientRect` 也正常，控制台零报错。

**根因**：`.fbox{z-index:2}`。矢量层是 `z-index:auto`，同级里被 `z-index:2` 的兄弟压住 ——
**DOM 顺序只决定同 z-index 的先后**，一旦有兄弟显式设了 z-index，后面插入的 auto 元素照样在下面。

**修法**：给矢量前景显式 `#vecF{z-index:3}`；顺带发现 `#gtags` 是 `position:static`，`z-index` 根本不生效，
要补 `position:absolute;inset:0`。
⇒ 通则：**"元素建了、opacity=1、就是不显示" 第一步查 z-index 栈，别查 DOM 顺序。**

### DB-13 · 组级 `style.opacity` 会把时间窗逻辑静默抹掉

**现象**：给每个画面建了 `VG[1..8]` 矢量组，用 `VWIN` 时间窗统一开关：
`for (k in VWIN) VG[k].style.opacity = on ? 1 : 0`。
随后为了让 P1 的元素各自淡出，又在循环后面补了一句 `VG[1].style.opacity = 1`（P2 也补了一句）。
结果 **P2 的尺寸线和 bit 方块在 P6/P7/P8 每一帧都在**，像散落的白色小方块。

**根因**：补的那一句在循环之后执行，**无条件覆盖**了窗口算出来的 0。
更隐蔽的是它只影响"窗外的画面"，窗内一切正常 ⇒ 抽查几帧全对，只有逐点扫才看得见。

**修法**：窗口逻辑只有一个出口，元素的个别淡出**乘**在窗口上（`q * f1`），不许再写组级 opacity。
⇒ 通则：**同一属性只能有一处写；"再补一句"是这类 bug 的唯一来源。**

### DB-14 · 矢量层的时间窗必须跟着它所属组的 fade 走

**现象**：`g6` 在 32.98 开始淡出、33.18 归零；`VWIN[6]` 却开到 33.65。
多出的 0.47s 里，卡片已经没了，矢量层的序号 `01` 还浮在 STUN 红框上。

**修法**：把窗口收到 33.08（略早于组淡完），宁可早 0.1s 也不留尾巴。
⇒ 通则：**给叠在内容上的装饰层设窗口时，端点取「内容组的 fade 结束时间」，不是「下一个画面开始时间」。**

### DB-15 · 「组可见」必须晚于「组已就位」：差 0.02s 就是闪一帧

**现象**：S08 的 P4→P5 垂直推移，播放时 22.88 附近闪一下——整排音频卡（MIC/ES8311/SPK）压在浏览器窗上。

**根因**：`render()` 每帧先把所有组的 `transform` 复位成 `none`，再按 `ON` 窗口设 `opacity`，
**最后**才跑推移动画。原代码 `ON.g5 = t >= 22.88`、推移 `if (t >= 22.90)` ⇒ 22.88–22.90 这两帧
g5 已经是 opacity 1，但 transform 还停在 `none`（原位）。30fps 下就是 1 帧重影。

**修法**：推移起点提前到 22.88（与可见性同帧），并把 `g4` 的可见窗口延到推移动画结束之后（23.58）。
⇒ 通则：**凡是"从画面外推入"的组，它的 `ON` 起点必须 ≥ 推动起点，`OFF` 终点必须 ≤ 推动终点；
　 两个时间常数之间差一帧，就会闪。**

### DB-16 · 「硬切 + 下一个元素已经淡入」= 两行标题叠一起

**现象**：S08 的 25.95 出现「ES8311 / ESP32-P4」两行字叠在同一位置，像渲染坏了。

**根因**：P5 的音频组在 26.00 被 `ON` 窗口**硬切**（没有 FADE），而 P6 的 P4 封装 25.92 就开始淡入。
两者重叠 0.08s，封装的白底 + "ESP32-P4" 正好压在 ES8311 卡上。
另外卡片收走后，波形/刻度还挂在半空 0.2s（孤儿元素）。

**修法**：① 给 `FADE` 补 0.12s 淡出，别硬切；② 卡片 25.70 起向目标节点「收缩归位」；
③ **波形/刻度/尺寸线要比卡片更早退**（25.58 起）—— 附属元素晚于主体消失就会变成孤儿；
④ 目标节点提前到 25.72 出现，让收缩"有地方可收"。
⇒ 通则：**转场里"消失"要分主次：主体先走附属后走是错的，附属先走才对；
　 而"出现"要反过来——接收方得先在场。**

### DB-17 · 叠在内容上的矢量层，不会跟着组的 transform 走

**现象**：S09 做垂直推移时，上一页的内容被推走，但那一页的矢量元素（格阵、尺寸线）**留在原地**，
像一片飘在半空的孤儿。

**根因**：矢量层挂在两个全屏 `<svg>` 上，不在 `.stg` 组里。组做 `translateY` 时只带走自己的子元素，
矢量层原地不动。窗口只要跨过推移区间，就必然露馅。

**修法**：把每段矢量窗口**整体避开推移区间** —— 出的一侧提前关（内容要走时矢量先收），
进的一侧等落位再开（`6.56–6.96` 推移 → 前段窗到 6.56、后段窗从 6.98 起）。
⇒ 通则：**装饰层的生命周期按「内容落位」算，不按「画面切换」算。**

### DB-18 · 垂直推移的位移量不能凭「一屏高」写死：大于内容高度就会推出中间一段空白

**现象**：S08 的 P4→P5 推移，播放时 **23.2–24.0 有 0.83 秒整屏几乎全空**（边缘强度 2.2‰）；
S09 同款推移在 6.83–6.93 也有 0.13 秒空。两处都在「推到一半」的位置。

**根因**：位移写成 `±1120`（≈一屏高）。但两页的内容并不占满画布 ——
S08 的 P4 内容在 **y 96–836**、P5 内容在 **390–750**；推到 p=0.5 时
出页在 −466…276、进页在 952…1490，**中间 276–952 共 676px 什么都没有**。

**修法**：位移量按「两页内容能在中途接上」反算 ——
`D ≤ 出页内容底 − 进页内容顶`（S08：836−390 = 446）。
再给出页补一段后半程淡出（`1 − clamp((p−.55)/.45)`），否则 p=1 时它还占着上半屏。
⇒ 通则：**推移距离不是"一屏"，是"两页内容的高度差"；写之前先把两页的 y 范围量出来。**

### DB-19 · 进页的内容必须和推移同时起，不能等推移结束

**现象**：S08 推完（23.58）之后画面还是空的；S09 的检测页在推移中只有一个 P4 小方块。

**根因**：推移 22.88 起，而进页的语音节点 23.42 才起、检测画幅 6.92 才起 ——
**推移前 0.5 秒里，进页只有零星元素在动，出页已经淡干净**。

**修法**：进页的主元素（画幅 / 卡片 / 节点）起点 = 推移起点，不要晚于它。
出页的淡出可以留到最后，进页的淡入必须一开始就有。
⇒ 通则：**换页的"有内容"是接力，不是交接 —— 接棒的人要在交棒的人松手之前就跑起来。**

### DB-20 · 全屏装饰层不能挂在带版面偏移的容器里

**现象**：S08 v4 / S09 v3 的图纸底「四角 L 形角标」，实测截图里只有**下半截两根断线**，
像画错了；左右边刻线也少了最上面一截。需求方没提，但它是错的。

**根因**：三段片子的 `#world` 都带 `top:-100px`（S08/S09 沿用的版面偏移），
两张全屏 `<svg>`（`#vecB`/`#vecF`）挂在 `#world` 里 ⇒ 所有 y 坐标被整体上推 100。
角标写 `y=52`，实际落在画面 `y=−48`，被 `#stage{overflow:hidden}` 裁掉。

判据也报了，但当时被当成噪音：`_bench.cjs` 输出 `{'x':32,'y':-48,'w':1856,'h':804}`，
而 S08/S09 的其它越界都是"转场飞行物"，这一条混在里面没被挑出来。

**修法**：把 `#vecB`/`#vecF` 挂到 `#stage` 下、`#world` 外，坐标直接用画面坐标：
```html
<div id="stage">
  <svg id="vecB">…</svg>
  <div id="world">…各场景组…</div>
  <svg id="vecF">…</svg>
</div>
```
```css
#world{position:absolute;left:0;top:-100px;…;z-index:1}
#vecB{z-index:0}  #vecF{z-index:3}
```
S10 干脆把 `#world{top:0}`，新段不再引入这个偏移。
⇒ 通则：**装饰层的坐标系必须和画布一致。任何 `top/left` 非零的容器，都不要往里放全屏层。**

### DB-21 · 组窗口的**起点**晚于组内最早入场时刻 ⇒ 元素的淡入被整组 opacity=0 吃掉

**现象**：S10 的 7.63–7.83（0.23s）整帧只剩一条存储块，扫片脚本判"连续低结构段"。
把标尺（P3 的先导元素）从 7.68 提前到 7.56，**扫出来一模一样，一点没变**。

**根因**：标尺在 `VG[3]` 里，而 `VWIN[3] = [7.70, 10.42]`。
`rVEC()` 每帧先按窗口把整组设成 `opacity:0`，再跑元素自己的 `style.opacity = 0.39`。
**父级的 0 乘任何子级都是 0** —— 7.56–7.70 那 0.14s 标尺根本不显示，
所以"提前入场"这个修改完全失效，而代码看起来是对的。

**修法**：组窗口起点 ≤ 组内所有元素的最早入场时刻。
`VWIN[3]` 改 `[7.54, 10.42]`（比起画时刻 7.56 再早 0.02）。
⇒ 通则：**窗口不是"这一页从哪开始"，是"这一页最早一个元素从哪开始"。
　 与 DB-14（终点取组 fade 结束）合起来：窗口要把组内所有元素的时序**包住**，不能切。**

### DB-22 · `el.style.opacity = parseFloat(el.style.opacity) * k` 每帧累乘，两秒归零

**现象**：S10 第一版 P2 的位宽格、P4 的六个车道块，本该淡出 0.18s，实际在 2 秒内
**持续变淡直到看不见**，而且不是从设定时刻开始，是从元素出现那一刻就开始。

**根因**：写成了
```js
e.style.opacity = (parseFloat(e.style.opacity || 0) * out).toFixed(3);
```
`render()` 每帧都跑，读到的是**上一帧自己写的值**，于是每帧乘一次 `out`（<1），
60 次调用后就是 `out^60`。表现是"渐变过慢且起点错位"，不报错、不闪烁，只是"慢慢没了"。

**修法**：opacity 必须由 t **纯函数**算出，每帧只写一次：
```js
const base = clamp((t - t0) / .20);      // 入场
const out  = 1 - clamp((t - t1) / .18);  // 退场
e.style.opacity = (base * out).toFixed(3);
```
⇒ 通则：**同一属性只许从时间重算，不许读自己上一帧的值。**
　 与 DB-13（补一句覆盖时间窗）是同一族：都是"同一属性有多处写"。

### DB-23 · 交叉淡出写成「A 到点退 / B 从同一点进」⇒ 切换点两张同时为 0，全白

**现象**：S07 的三张 GitHub 截图依次 swap，播放时四个切换点各有 0.2–0.5 秒**全白**（`_flashscan` 报 0.0‰）。
第一版还在 S09/S10 见过 2.2‰，这次是彻底的白。

**根因**：窗口公式写成首尾相接
```js
const q = Math.min(clamp((t - t0) / .34), clamp((t1 - t) / .24));
SEQ = [[W1, 0.40, 3.30], [W2, 3.30, 7.30], ...]
```
`t = 3.30` 时：W1 的 `(3.30-3.30)/.24 = 0`，W2 的 `(3.30-3.30)/.34 = 0`。
**两张同时 0**，画面上什么都没有。

**修法**：相邻两段的窗口**交叉重叠**一个 fade 时长（0.26s）：
`W1 = [0.02, 3.52]`、`W2 = [3.26, 7.52]`、`W3 = [7.26, 10.80]`。
⇒ 通则：**凡"A 退 B 进"的交接，A 的终点必须 ≥ B 的起点，重叠量 ≥ 一次淡入。
　 首尾相接 = 中点必空，这不是"可能出问题"，是必然。**

### DB-24 · 组窗口的**终点**晚于组内最后一个元素的退场 ⇒ 中间整段只剩底板

**现象**：S07 的 P4 讲完三处改动后，12.92 之后到 P5 开始（14.72）之间 **1.8 秒画面只剩图纸底**。

**根因**：`rP4` 里所有元素的 `out = 1 - clamp((t - 12.92) / .14)` 在 13.06 就归零，
而 `ONS.g4 = [10.40, 14.72]` 把组开到了 14.72。组还亮着，里面全透明。

**修法**：组窗口的终点必须 **≤ 组内最后一个元素的退场完成时刻**，或者反过来把元素的 `out`
推迟到窗口终点之前 —— 两者取其一，不能一个 12.92、一个 14.72。
⇒ 通则：**窗口和元素时序要互相"包住"：窗口起点 ≤ 最早入场（DB-21）、窗口终点 ≥ 最后退场。
　 两头都不能留缝。**

### DB-25 · 一处抛错会让整段 `<script>` 停止执行，而 `function` 提升让它看起来"还活着"

**现象**：S07 的 `markBox` 里写了 `win.map(...)`（`map` 实际挂在 `host` 上），抛 TypeError。
表现不是"画面坏了"，而是 **`render(1.9)` 报 `Cannot access 'ONS' before initialization`** ——
一个和真因毫无关系的 TDZ 错误。

**根因**：`const ONS = {...}` 在抛错处之后，永远没执行；而 `function render(){}` 是**函数声明**，
被提升到作用域顶部，所以 `window.render` 有值、可调用。调用时才碰到 TDZ 的 `ONS`。
⇒ 看起来像"变量没定义"，实际是"前面的代码把脚本打断了"。

**修法**：① 先修真因；② 给 `render` 包一层 `try/catch`，别让一处错毁掉整支片子；
③ **看 `pageerror` 而不是只看"render 能不能调"** —— 页面报错被 puppeteer 的 `pageerror` 事件接住，
不看就完全无感。
⇒ 通则：**`script` 是单线程顺序执行的，任何一处 throw 都会让后面的 `const` 全部作废。
　 排查"变量未初始化"时，先往上找**第一处**报错，别在 TDZ 那一行打转。**

### DB-26 · 「先给完整画面、再把元素拆散重演」是**语义**错误，不是动效风格问题

**现象**：需求方看 S07 v2 原话：「**你做的有点太刻意了，要么就是从空白页直接做效果，要么就直接出现完整的，
哪有出现完整的再重新弄效果的**」。抽帧验证：t=0.22 整页 16 行文件列表**完整**，t=0.95 中间被吃出两条空白带。

**根因**：抄 S31 的 `row-embed` 只抄了技术、没抄前提。S31 那个配方演的是"页面**正在**组装成完整"，
所以行必须是**从无到有**。S07 的 P1 先做 `panel-drop`（整块窗口带着完整页面落下来），
再逐行 `row-embed` —— 观众看到的顺序变成 **完整 → 拆散 → 又完整**，比 PPT 翻页还退步。

**修法**：`patch`（那一行的白洞）从 **t=0 就存在**，`img` 延到 0.16–0.72 才浮现。
观众看到的是：白窗口落下 → 页面浮现、文件列表是空的 → 行一条条填满。
⇒ 通则：**任何"组装"类动效，容器的初始态必须是"缺的"，不能是"完整的"。
　 先给完整 = 先剧透答案，后面的动作全成了多余。**
　 反例同族：S10 的 P1 存储块先给整条再点亮 3 格 —— 那个可接受，因为点亮是"标注"不是"组装"。

### DB-27 · 行槽的位置和它自己的 `background-position` 必须由**同一个 y** 推出

**现象**：改完 P1 后，每个"洞"里显示的是**上一行的半截**，看起来像半透明的残影叠在一起
（抽 1:1 帧看到 `esp-webste-solution` 的同名残影和真实列表错开 34px）。

**根因**：为了让"7 行对上列表第 2–8 行"，只在 `backgroundPosition` 上减了 `41·sc`，
槽位 `slotTop` 没跟着减。结果槽在 167.8、背景切的是 183.7，差整整一行。

**修法**：槽位和切位用同一个 `Y0`：
```js
slot.top              = Y0 * sc - crop.y * sc;
row.style.backgroundPosition = `-${X0*sc}px -${Y0*sc}px`;
```
⇒ 通则：**一个元素只要"自身位置"和"内部内容的偏移"同时依赖某个基准，这个基准只能有一份。
　 调基准时两处一起改；改一处 = 内容相对自身错位，而错位量刚好等于一个行高，看着像"渲染糊了"。**

### DB-28 · 设计稿的坐标口径要当面问清：`top` / `bg` / `background-position` 是三个坐标系

**现象**：设计稿给 `{ top: 385.9, bg: '-160.3px -217.9px' }`。看着像"top 是屏上坐标、bg 是图像偏移"，
实际 `385.9 − 168（窗口 y）= 217.9 = |bg.y|` —— **`bg` 给的就是窗口内位置**，不是图像偏移。

**根因**：三个坐标系混在一起：
① 画布坐标（含窗口偏移 292/168）② 窗口内坐标 ③ 缩放后图像的内部偏移（要再加 `crop·sc`）。
设计稿用一种、实现用另一种，差一个 `crop.y·sc`（P1 是 50px、P3 是 150px）。

**定位方法**：找一个已知元素反推。`385.9 − 168 = 217.9`、`452.3 − 292 = 160.3`，
两个数都和 `bg` 完全一致 ⇒ 立刻能确定 `bg` 的口径。

**修法**：`slotTop = top − 168`、`bgY = slotTop + crop.y·sc`。
⇒ 通则：**拿到坐标表先做一次"减法校验"**（挑两个已知量互减，看结果等于哪个数），
　 口径确定后再写代码。少这一步，后面所有微调都是在错误基准上叠错误。

### DB-29 · 组窗口（`ONS`）的三段必须首尾相接，缝留在帧级别（≤0.10s）

**现象**：`_flashscan` 报两段 **0.0‰**（画面完全没有边缘）：10.20–11.87（1.70s）、14.77–17.10（2.37s）。
抽帧确认 t=15.00 **整帧全空**，只有图纸底。

**根因**：`ONS = { g1: [0, 10.34], g4: [10.43, 14.86], g5: [15.50, 99] }` ——
`g4` 关到 14.86，`g5` 从 **15.50** 才开，中间 0.64 秒没人负责。
而 P5 的元素 `opacity` 在 14.72 就算好了，组一开就是满的 ⇒ 从"全空"硬切到"两张卡都在"。

**修法**：`g4` 到 14.58、`g5` 从 14.66（0.08s = 2.4 帧换气）。
⇒ 通则：**组窗口是一份"谁在负责画面"的值班表。任意时刻必须恰好有一个组在岗。
　 空档 = 观众看到一张空底；重叠 = 两套语言同框（S07 的 P4 压截图就是这种）。
　 换气缝只留帧级（≤0.10s / 3 帧），超过就是事故。**

### DB-30 · 字幕按字数硬切 = 断在半句（零报错，只有人看得出来）

**现象**：英文版 131 条字幕，技术指标全绿（时长、条数、与词轴对齐都对），
需求方播完只留一句：「**又是没有按句号或者是在适当处断开，我昨天搞了好久**」。他手工重切了 15 处。

**根因**：切分逻辑是「超过 ~60 字符就切」，切点落在第 60 个字符上，不看语法。
于是出现 `...for the call at a` ｜ `target 15 fps,`、`...are both served by the` ｜ `P4 on the same LAN,`、
`...public STUN` ｜ `wait and turned off...`、`...buffers and` ｜ `formatting`、`...page was` ｜ `reworked`。
**每一条单独看都是完整的词，连着读才知道下一行是硬接的。**

**为什么一直没被发现**：字幕不在七道判据的覆盖范围里 —— `overlap` 管压字、`density` 管密度、
`comp_pos` 管构图，**没有任何一条判据看"句子断没断"**。而且它不影响渲染、不影响音画同步、
不影响出片，所以整条链路一路绿灯。

**修法**：
1. 切点优先级：句号 > 分号/冒号 > 逗号 > 从句起点 > 介词短语前；
   **禁切点**：冠词后 / 介词后 / 连词后 / be 动词后 / 程度词后 / 名词短语中间。
2. 字数只作上限，到上限还没到边界就**往前找**最近的合法切点（宁可长短不齐）。
3. 新立体检器 `subsplit_audit.py`（skill `blueprint-motion-system/scripts/`），
   **HARD 与 LONG 必须 0**，且**先跑 `--selftest` 负控**证明判据没瞎。

**实测对照**：我 131 条 → HARD 6 / LONG 3；需求方 127 条 → HARD 0 / LONG 0。

**★ 通则：凡是"人能一眼看出不对、但机器全线绿灯"的东西，说明判据族缺一个维度。**
　 这次缺的是「语言边界」——判据只覆盖了像素和几何，没覆盖文本。

**负控踩到的子坑**：第一版体检器自造的负控样本只有 58 字（没到 60 上限），
超长那条**根本没机会报红**，却差点因为"3 个硬切都抓到了"被当成 PASS。
⇒ 负控样本必须**逐个跨过被判的阈值**，否则测的只是"另一条判据"。

### DB-32 · PSRAM 被逐字母读成 P-S-R-A-M

**现象**（需求方 2026-11-26 指出）：「P S-RAM 读音后面的 ram 是一个单词来的，不是分开来读」。听感是四个字母一个个念。

**根因**：edge-tts 对全大写无空格缩写按字母展开读，`PSRAM` 一个 token 进去、四个字母出来。

**修法**：TTS 文本写成 **`P S ram`**（中间空格、ram 小写）。词轴实测：`P | S | ram` 三个独立 token，读作 "pee ess ram"。
- 不要写 `P-S-ram`：词轴只有一个 token `P-S-ram`，读法不可控。
- 同类缩写（PSRAM / SPIRAM / QSPI 里的 RAM 部分）照此处理。

**影响面**：改读音 = 重写音频 = 音频内嵌在 html 里 ⇒ **必须重跑该镜头的构建脚本 + 重渲视频**，不能只换草稿里的配音段。

### DB-33 · EN 视频替换进草稿后整段没声音（has_audio=True 也没用）

**现象**（需求方 2026-11-26 截图）：时间线上 S04-01 / S04-02 / S04-03-04 等视频段**没有音频波形**，播放无声。素材 `has_audio=True`、段 `volume=1.778`（+5dB）看着都正常。

**根因（2026-11-26 二次返修后定论，一共三层）**：
1. **视频自带原声这条链不可靠** —— 素材是脚本新写入草稿的（新 id、新路径），剪映没为它建立音轨缓存，`has_audio=True` + `volume=1.778` 也不出声、时间线连波形都没有；
2. ★★★ **新建音频素材的 `type` 必须是 `extract_music`**。我第一版用 `next(iter(AUD.values()))` 随便取模板，取到了 `type='sound'`（音效类型）⇒ 剪映的音效素材加载路径**不读本地磁盘文件**，段放上去波形是一条直线、播放没声。草稿里所有能出声的素材都是 `type='extract_music'` + `category_name='local'`；
3. **路径里不许带 `..`** —— `os.path.join(HERE,'..','audio',...)` 拼出来是 `../audio/...`，Python 能 `isfile`，剪映的加载器不解析。必须 `os.path.normpath`。

**为什么两次都没查出来**：第一次只看「字段齐不齐」（has_audio / volume 都在）；第二次只看「文件在不在」（`os.path.isfile` 全 True）。两次都在**自己的判据面**里是对的 —— 判据面里根本没有「素材类型」和「路径规范化」这两个维度。

**修法：一律分离音频**（需求方原话「中文版是分离了音频，英文版也可以分离出来」）：
1. `ffmpeg -i 成片.mp4 -vn -ac 1 -ar 48000 -c:a pcm_s16le x.wav` 抽音频；
2. **新建一条 audio 轨**（`copy.deepcopy` 现有 audio 轨 → 换 id、清空 segments → append 到 tracks），**不要塞进已有音效轨**（会与音效段重叠，实测 T14 上 10.53–35.58 压掉三条音效）；
3. 段起点 = 视频段起点，`source_timerange` 按 B4 那种拆段截取（0 / 11.64）；
4. **视频段 `volume=0`**，避免以后能出声时双声；
5. 段模板别用音效段，用**已验证能出声的配音段**（T18 那种）deepcopy。

**格式统一 mp3**（192k）：草稿里全部能出声的音频都是 mp3，wav 虽然剪映也认，但和存量不一致时容易多一层怀疑对象。

**判据**：视频段 volume 全 0；旁白轨段数与视频段一一对应且起点差 < 10ms；音频素材 mean ≈ −17dB（有声）；轨内零重叠。

### DB-36 · 字幕照抄中文时间、配音按英文速度重排 ⇒ 两套时间轴对不上（差 2.5 秒）

**现象**（需求方 2026-11-27）：「你的字幕跟语音是对不上的」。修复前的实测：字幕第 10 条 `Blue side faces up` 在 23.63 就换出来了，配音到 26.13 才说 —— **字幕抢跑 2.5 秒**；后半段更乱（字幕按中文 3 秒一换，配音 2 秒就说完了）。

**根因（一句话）**：我把「字幕时间」当成了**画面标注**，认为它跟着画面走、不能动；于是只换文本、时间原样，而配音按英文实际语速重新排了一遍 ⇒ **两条时间轴各走各的**。

**区分两种「画面上的文字」**（这次唯一没分清的东西）：
| 类型 | 例子 | 时间跟谁走 |
|---|---|---|
| **台词字幕** | 视频底部那一行旁白 | **跟语音**（词轴），语音多长它就多长 |
| **物料标注** | 「杜邦线×2」「7-inch display」贴在实物旁边 | **跟画面**（镜头），不能动 |

**正确做法**：
1. 先定配音：TTS 拿到**词级时间戳**（`boundary='WordBoundary'`）；
2. 字幕由配音文本按语法边界切（>45~55 字符才切一条），
3. 每条字幕的 `start` = **配音段起点 + 该条首词的词时间**，`end` = 末词时间（不够 1 秒的补到 1 秒）；
4. 字幕条数**允许变**（中文 28 条 → 英文可能 25~32 条）：多的删段、少的复制新建段。

**判据（必须跑）**：对每一条字幕，找到时间上覆盖它的配音段，断言
`字幕起点 ∈ [配音起点-0.2, 配音起点+配音时长]`，且字幕条数与配音文本切分结果一致。
**这条判据只用量化时间就能验，不需要听** —— 我上一版恰恰是"没跑判据、凭肉眼觉得排得对"。

**为什么一开始会错**：中文稿里字幕和配音本来就是分开的两条轨，字幕是「按语义提前一点出、配着画面念」，天然比配音早 1~3 秒；我把这个"中文的提前量"当成规则照抄到了英文上，而英文的语速和断句完全不同，提前量一叠加就成了 2.5 秒。

### DB-37 · 字幕文字和语音说的不是同一句（TTS 缓存不校验文本 + 收尾只查时间不查内容）

**现象**（需求方 2026-11-27）：「有些语音的字幕是对不上的」。实测三条：

| 段 | 字幕显示 | 语音实际说的 |
|---|---|---|
| 1 片头 | `The WT9932P4C61-TINY` | `**This video shows** the WT9932P4C61-TINY` |
| 2 | `official Espressif 7-inch display` | `**connecting an** officially Espressif-**compatible** 7-inch display` |
| 9 | `Connect the FPC to the board's MIPI DSI port` | `**First** connect the FPC **cable** to the board's MIPI DSI port` |

时间是对齐的（起点都在原位），所以**看时间轴看不出问题，只有把两边的文字并排才看得见**。

**根因（三层）**：
1. ★ **TTS 缓存键不含文本**：文件名是 `v3_%02d_%s.mp3`（段号 + 语速），我改过句子后缓存照样命中 ⇒ 配音还是**旧句子**。而字幕文本取的是 `VOICE_ALL` 的**最新**英文 ⇒ 两条来源分叉。
2. 改文本时只想着"改字幕更短更贴合"，没意识到音频是缓存产物、不会跟着变。
3. **收尾检查的判据面缺一个维度**：我只查了「字幕起点是否落在配音区间内」（时间覆盖），没查「字幕文字是否等于语音念的词」（内容一致）。时间对、文字错，判据全绿。

**修法**：
- TTS 缓存文件名加 `md5(文本)[:6]`：`v3_01_10_a3f9c2.mp3` —— 文本一改，文件名就变，必然重新生成；
- 收尾审计加**词级比对**：把字幕文本和语音词轴都 norm 成词集，`len>2` 的词做差集，
  `语音有字幕无 > 2 词` 或 `字幕有语音无 > 2 词` ⇒ FAIL（并打印具体差异词）；
- 审计脚本 `接线教程片/_p4c61_audit.py`，7 项检查，输出 PASS / FAIL。

**判据（收尾必跑，不许靠肉眼）**：
```
python _p4c61_audit.py "<草稿>/draft_content.json"
```
必须 `判定：PASS`，且 `有问题的配音段：0 / N`。7 项：
① 每段配音都有字幕 ② 首条字幕起点 ≈ 段起点−0.10 ③ 字幕不超段尾
④ **字幕文字 ≈ 语音念到的词** ⑤ 字幕 0 重叠 ⑥ 配音 0 重叠 ⑦ 残留中文配音 0

**为什么这次特别难发现**：文本改动是我自己做的（为了压时长），缓存复用是"优化"带来的副作用 ——
**优化和正确性打架时，优化必须让路**。缓存键只要不包含"决定产物内容的全部输入"，就一定会出这种问题。

**同类风险**：任何"改了输入但产物没重算"的地方 —— 归一后的 `_n.mp3`、渲染缓存的帧、导出的 wav，
凡是拿旧文件当新结果的，都要检查缓存键是否覆盖了全部输入。

### DB-38 · 英文配音「比中文长」的主因不是语速：edge-tts 每段尾拖 0.78s 静音 + 三条轨被当成一条序列排

**现象**：P4C61 英文版前半段（0–27 秒）整体推后 1.3–2.2 秒，需求方两次说「没跟中文版对齐」。

**根因 A：每段尾巴一段固定静音**。实测 29 段，`silencedetect` 显示**每段末尾 0.77–0.80 秒静音**（段 5 总长 1.87s，其中 1.10–1.87 全是静音）。
29 × 0.78 ≈ **22 秒**——不是英文说得慢，是尾巴太长。「装不下」的 15 段里有 9 段裁掉尾巴后就装得下。

**根因 B：三条轨被当成一条序列**。29 段分散在 T18/T19/T20，中文原版**本来就允许跨轨交叉**：
段 1（T19, 0.00–3.50）与段 2（T18, 3.37–6.64）**重叠 0.13 秒**。按「全局一条序列」排轴时，
段 1 变长 0.9 秒就把段 2 往后推，一路连锁到段 10，累积 2 秒——而实际上它们根本不在同一条轨上，不需要互让。

**修法**：
1. 归一后加一步**裁尾**：`silencedetect` 找贴着结尾的静音段，`silence_start + 0.15` 处截断（留 0.15s 自然尾音），重新编码 mp3；
2. **按轨排轴**：`cursor` 按 `track_index` 分开维护，同轨顺延、跨轨允许交叉；
3. 字幕仍是一条轨，跨轨配音交叉时**前一条字幕提前收**（只切尾巴，不切文字）。

**结果**：29 段起点**全部等于中文原起点**（零推后），各轨结束 42.84 / 99.35 / 85.32 均在原范围内。

**判据**：排轴表里不应出现任何 `推 +x.xx`；若出现，先查两件事——这段尾部静音裁了吗？这段和上一段是同一轨吗？

**教训**：「英文天生比中文长 30–50%」这个判断是错的。**先量，再归因**——我拿"语速快慢"解释了三轮，
真正的原因是静音和轨道结构，两者都不是语言问题。

**现象**（需求方 2026-11-27 截图）：S02 锁位帧里左边 `NTRODUCTION`（I 被切）、右边 `WT99P461-S1` 结尾被切，两边都顶出画幅。

`left = (1920 - subject - gap - model) / 2`，**没有越界判断**。中文够短所以一直没暴露；换成
`INTRODUCTION`（实测约 860）后总宽约 1990 > 1920，`left` 算成负数，两边各裁约 35px。

**修法**：`measureOpening()` 里改为**实测 + 装不下就缩**：
```js
const gapMax = openingBoardHeight * openingBoardRatio + 128;
const avail = 1920 - 120;                       // 左右各留 60px 安全边
const glyphs = (subject + model) * openingGlyphScale;
if (glyphs + gapMax > avail) openingGlyphScale *= (avail - gapMax) / glyphs;
```

**判据（必须看，不是看中间）**：文字块左右距画幅边 ≥ 40px。用 `--stills` 出**锁位帧**（本例 4.2s / 5.2s）
直接看，别等渲完 3 分钟。凡是"把中文换成英文"的页面，**所有按中文字宽/字数算的坐标都要重新实测**。

**同族**：DB-31（播放器 UI 被拍进成片）、DB-41（片头话塞进章节）——都是"按中文稿的假设做英文稿"。

### DB-43 · 英文版时长超过中文版 ⇒ 后续画面和字幕全部错位

**现象**（需求方 2026-11-27）：「在草稿那里是完全对不上的」「时长不要超过中文版很多，因为超过的话后续的画面和字幕也就跟着错位了」。

S02 被做到 **25.50s**，中文原版 **21.467s**（+4.03s）。为了不让音画错位，全片时间轴整体后移：
S04-01 从 128.100 推到 132.133，片长 206.067 → **213.600**。需求方的剪辑点、实拍段、字幕全部跟着漂。

**根因**：我把「时长」当成了可调项。**时长是别人剪辑点的契约**，不是我这支片子的自由度。
为了让英文念全 + 不裁尾，选择"把片子拉长 4 秒"——这个决定权根本不在我。

**正确顺序（压缩优先级，逐级用，不许跳级）**：
1. **裁每段尾部静音**：edge-tts 每段尾固定 0.77–0.80s，四段就是 3 秒（DB-38）；
2. **缩句间过渡**：0.25 → 0.12s，中文原版本来就几乎零间隙；
3. **提语速**：允许 +10%，实测装不下可到 +13%（上限 +15%，超过就明显赶）；
4. **动画 warp 贴中文时间轴**：EN 总长 = 中文剪后长度，画面按中文原速走；
5. 仍然装不下 ⇒ **回来找需求方裁语义**，不许自己删（DB-39）。

**结果**：四段 +13% + 裁尾 + 0.12 间隙 = **21.40s ≤ 21.467s**；S02 段回到 `10.533 + 21.467`，
S04-01 回到 `128.100`（与中文原版逐一相等），片长 213.600 → **209.567**。

**判据**：每个替换段的 `target.start` 必须等于中文原稿的同名段起点（差 < 10ms）；
片长只允许因"新增/删除整段"变化，**不许因"英文说得慢"变化**。

### DB-44 · motion code 有两份：外部 .js 和 HTML 内联，只改一份 = 渲染读旧代码

**现象**：构建脚本打印 `EN_FRAMES=644（21.47s）`，渲染出来的视频读数仍是 `25.10`，音画对不上。
需求方看到的"完全对不上"有一半是这个原因。

**根因**：S02 是**单文件 HTML 交付**，JS 被内联进 `<script>`；同时目录里还留着一份
`motion-v2-EN.js`。构建脚本改的是外部 js，渲染（`--html`）读的是 HTML 内联那份 ⇒ 改了白改，**且不报错**。

**修法**：构建末尾强制同步并断言（`_sync_s02_html.py`，已内置进 `_build_s02.py`）：
把外部 js 的 `EN_FRAMES` / `WP` 写回 HTML，再 grep 回读比对。

**判据**：渲染前 `grep "const EN_FRAMES" <html>` 必须等于构建打印的帧数；渲染后
`ffprobe` 时长必须等于 帧数/30。**"构建成功"不等于"产物是新的"**——同一类病还有 DB-31
（`--query` 没传下去）、DB-37（TTS 缓存键不含文本）。
