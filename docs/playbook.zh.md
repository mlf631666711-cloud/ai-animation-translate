# 开工必读 · 英文版视频生产线

[中文](playbook.zh.md) · [English](playbook.en.md)

这份文档是给执行者（人或 agent）看的操作规约。每条都对应一次真实翻车，括号里是缺陷编号，正文在 [缺陷库](bugs.zh.md)。

> 阅读顺序：本页 → [一键流程](pipeline.zh.md) → 具体缺陷。不要反过来，先看缺陷会抓不住重点。

## 0. 三条硬规矩

1. **时长是剪辑点的契约**。英文版每个替换段的起点必须等于中文原稿同名段的起点，差 < 10ms。超了就会把后面的实拍、字幕、音效全部推走。
2. **语义不许为时长让路**。删词只能删语助词和重复表述；动词、限定词、数字一个都不许丢。装不下用工程手段压，压不下回来问人。
3. **交付前跑脚本审计，输出 PASS 才算完**。肉眼过一遍不算检查。

## 1. 翻译

- 翻译单位是**语义整句**，不是字幕条。中文字幕和配音都被切碎过，先合并成整句再翻。
- 判据：连着读语义没完，就是同一句（例："首先将同向线" + "连接开发板的 MIPI_CSI 接口和转接板"）。
- 一条整句上屏时拆几条字幕，是排版的事；翻译阶段不拆。
- 型号、单位、数字原样保留。英文按口播精简，不逐字直译。
- 先出整句译文，再按语法边界切成字幕条。两件事分开做。

## 2. 翻译前盘点（先盘点、后翻译）

跳过这一步，最常见的后果是：成片一半中文一半英文，而所有时间轴判据都是绿的。

四步，一步都不许跳：

1. **列全片中文字幕**：扫所有文本轨，不只段数最多的那条。要分清「台词字幕」和「画面标注」。
2. **逐条找配音**：配音可能分散在**多条音频轨**上。实测一例：29 段配音分在三条轨（2 / 19 / 8 段），只看段数最多的那条会漏 10 段。
3. **确认归属**：每一条字幕是「有配音的台词」还是「无配音的画面标注」。前者跟语音，后者跟画面，时间规则完全不同。
4. **确认完再翻**：字幕条数与配音段数要对得上，差异要有解释。

**判据**：翻译前打印一张表——`字幕序号 / 时间 / 中文 / 对应配音段（轨号 + 时间）`，缺配音的行显式标 `无`。这张表没打出来，不许开始翻译。

## 3. 时长：按中文版编排

压缩优先级，逐级用，不许跳级：

1. **裁每段尾部静音**。edge-tts 每段尾固定拖 0.77–0.80 秒，四段就是 3 秒。这条最容易被忽略，也最有效。
2. **缩句间过渡**。0.25 → 0.12 秒；中文原版句间本来就几乎零间隙。
3. **提语速**。默认 +10%，装不下可到 +13%，上限 +15%。再快就听得出赶。
4. **动画 warp 贴中文时间轴**，让画面按中文原速走。
5. 还装不下 ⇒ 回来找人裁语义。

**判据**：渲染前打印「英文总长 vs 中文时长」，必须 ≤。超了不许渲。

## 4. TTS

- 英文：edge-tts，`en-US-JennyNeural`。中文（对照稿）：剪映文本朗读。
- 词级时间戳要传 `boundary='WordBoundary'`，默认只给句级。
- 响度归一 −17 dB。单声道转立体声会掉 3 dB，先转格式再测再补增益。
- **缩写要「字母 + 词」拆着写**：`PSRAM` 会被逐字母读成 P-S-R-A-M，写成 `P S ram` 才读 "pee ess ram"。`P-S-ram` 也不对（合成一个 token）。
- 测 `volumedetect` **不能加 `-v error`**：统计是 info 级，会被一起吞掉，`mean_volume` 读回垃圾值（踩过：增益算成 +82 dB，输出直接静音）。
- **TTS 缓存键必须含文本 hash**：`v3_%02d_%s_%s.mp3 % (段号, 语速, md5(text)[:6])`。只按段号 + 语速缓存，改完句子仍命中旧音频 ⇒ 配音说旧句、字幕显示新句。凡是"拿旧文件当新结果"的地方（归一后的 mp3、渲染帧、导出的 wav），都要检查缓存键是否覆盖全部输入。

## 5. 字幕

- 切点顺序：句号 > 分号/冒号 > 逗号 > 从句起点 > 介词短语前。
- 不在冠词、介词、连词、be 动词、程度词后面断；名词短语内部不断。
- 字数只作上限，不作切分依据。到上限还没到边界，往前找合法切点。
- 英文单条上限 65 字符（约等于中文 21 个全角字宽），以本片中文原字幕最宽行为参照。
- 切点用词级时间戳，不用字符比例估。
- 逗号后不留空格，条尾不留空格，字幕条末不加句号。型号、单位、数字整块不拆。

## 6. 动画英化

只换文字不算英化。交付判据是**动画跟着英文语音走**。

- 顺序固定：中文整句 → 英文整句 → TTS（mp3 + 词级时间戳）→ 音频内联 → 按词轴重排动画。
- 重排用分段线性 `warp(x)`：`WP = [[英文时间, 中文时间], …]`，英文时间喂进去，映射回中文原时间轴。
- `warp` 必须单调不回退，`warp(0)=0`，末点映射到中文剪后总长。
- 全局比例 `x * 中文/英文` 只能用于没有局部节奏差的段。中英信息密度不同就必须分段，否则场景切换会早于或晚于说出的词。
- 场景边界对到语义最近的词（说 "capture" 时才出 Capture），不对到按比例算出来的时刻。
- 时间轴硬编码进模块的片子：不改 `VOICE` / 帧号，只加 warp 双层映射——英文播放时间 → 中文 edited 时间 → 原有 `animationTime()`。
- 换完音频抽帧验证：每个切换点前后各一帧，画面应与语音内容对应。

## 7. 画面越界体检

文字被画幅裁掉，往往渲完才发现，返工成本最高。

- **换文案就重测宽度**。凡坐标/字号是按中文字数或固定 px 算的（`openingWidths`、`left = (1920 - ...)/2`），换成英文必须改为运行时 `offsetWidth` 实测；装不下按可用宽度等比缩。只居中、不判越界，一定出事。
- **看锁位帧，不看中间**。用 `--stills <关键秒>` 出静帧，专看四边——出画的元素永远在边上，中间永远是对的。
- 判据：文字块左右距画幅边 ≥ 40px，上下 ≥ 24px；板卡/图片不许切边。
- 抽帧要覆盖「文字最多的那一帧」，不是均匀抽几帧了事。

## 8. 单文件 HTML 的 JS 有两份

单文件交付的页面里 JS 是内联的，目录里往往还留着一份外部 `.js`。构建脚本改了外部那份、渲染读 HTML 内联那份 ⇒ 改了白改，且不报错。

- 构建末尾把 `EN_FRAMES` / `WP` / 渲染函数一起同步进 HTML，并 grep 回读比对。
- 渲染前 `grep "const EN_FRAMES" <html>` 必须等于构建打印值；渲染后 `ffprobe` 时长必须 = 帧数 / 30。

## 9. 出片与草稿

- **带播放器的单文件 HTML 必须进「裸模式」**。不隐藏的话，渲出来是封面播放按钮或 Play / 进度条。约定 `?t=<秒>`（抽帧）或 `?export`（整片）触发 `body.bare`，CSS 里 `body.bare #ctl/cover/.tools { display:none }`。渲染器的 `--query` 参数要确认真的传到了主渲染分支（曾经只传给静帧分支）。
- **预览页 `.preview` 定宽 1320 会把 1920 的舞台裁掉**。导出模式要同时把容器撑到 1920×1080。
- **换进草稿的视频一律分离音频**：视频轨 `volume=0`，语音抽成 wav 放新建的旁白轨（不要塞进已有音效轨，会重叠）。剪映对脚本新写入的 mp4 原声轨经常不认，`has_audio=True` 也不出声，看波形就知道。
- **新建音频素材三个硬条件**，少一个就静音且不报错：
  1. `type='extract_music'`（不能是 `sound`，音效类型不读本地文件，波形是一条直线）；
  2. 路径过 `os.path.normpath`，不许带 `..`；
  3. 段模板从**已验证能出声的配音段** deepcopy，别用音效段。
  格式统一 mp3（192k）。
- **加到时间线的素材必须同步进素材箱**。素材箱不在 `draft_content.json` 里，是两处：
  1. `draft_meta_info.json` 的 `draft_materials` 里 `type=0` 那组（该文件是加密的，要先解再写）；
  2. `draft_virtual_store.json` 的 `draft_virtual_store` 里 `type=1` 那组，每条素材补一条 `{child_id, parent_id: ""}`，否则面板里挂不上根目录。
  条目字段：`metetype` = `video` / `music`，音频 `width/height = 0`，`md5` 留空，`roughcut_time_range` = 全片。
- **写回前关剪映**；写完同步 `Timelines/<uuid>/draft_content.json`；加密前做往返校验，不一致不落盘。
- 编码脚本拒绝覆盖，新版另存版本号。渲染帧可删，母版必留。

## 10. 收尾审计（必须跑）

七项，缺一不可：

1. 每段配音都有字幕覆盖（不能有「有声音没字幕」的段）。
2. 首条字幕起点 ≈ 配音段起点 − 0.10（±0.30）。
3. 字幕不超出所在配音段结尾。
4. **字幕文字 ≈ 语音实际念到的词**：两边 norm 成词集，`len > 2` 的词做差集；`语音有字幕无 > 2 词` 或 `字幕有语音无 > 2 词` ⇒ FAIL，并打印差异词。
5. 字幕段之间 0 重叠。
6. 配音段之间 0 重叠。
7. 残留中文配音（`text_to_audio`）0 段。

排轴还有两条硬规则：

- **先裁尾部静音**再排，否则"英文比中文长"是假象。
- **按轨排轴，不是按全局序列**。配音可能分在多条轨，中文原版允许跨轨交叉；cursor 按轨分开维护，同轨顺延、跨轨互不让。排完表里不应出现 `推 +x.xx`。

老草稿的坑：`version=360000` 那类草稿里，轨道 `type` 全是 `mixed`（不分 text/video/audio），且**第 1 段常常不写 `target_timerange.start`**（表示从 0 开始）。审计脚本要按 0 处理，否则会跳过它，表里显示"少一条"。

## 11. 交付

- 先出 HTML 预览让人确认，再渲 4K。
- 4K 只出一版（语音带音效）。不再单独导 1080p 预览。
- 需要竖版时由平台裁，不在制作流程里另出一版。
- 交付时写清：片长、替换段位置、回退点（备份文件名）。
