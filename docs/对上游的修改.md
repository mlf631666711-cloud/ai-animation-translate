# 对上游 pyJianYingDraft 的修改

上游：[aoguai/pyJianYingDraft](https://github.com/aoguai/pyJianYingDraft)（Apache-2.0）。
本仓库**不是原样引用**，而是在它之上做了改造。本文逐条列清楚：改了什么、为什么改、代码在哪。

---

## 一、没有改的部分

| 文件 | 说明 |
|---|---|
| `tools/jianying/_jc/draft_crypto.py` | 调用本机 `videoeditor.dll` 完成加密/解密。**算法与调用方式保持上游原样** |
| `tools/jianying/_jc/draft_codec.py` | 草稿 JSON 的读写封装（`load_json_object_with_codec` / `write_json_object_with_codec`），**原样** |
| `videoeditor.dll` | 剪映自带，**绝不修改**。只通过 ctypes 调用 |

我们保留上游的许可证文件：`tools/jianying/_jc/LICENSE-apache2.txt`。

---

## 二、改了的部分

### 1. 索引写入：密文 → 明文（必须改，否则剪映读不到草稿）

- **上游做法**：`draft_registration` 用同一个 codec 写 `root_meta_info.json`。
- **问题**：剪映 11.6 的这个文件是**明文**。用 codec 写会变成密文，剪映按明文解析 ⇒ 索引里看不到草稿。
- **我们改成**：`swap_draft.py` 直接 `json.dump` 写明文，并做三件事：
  1. 删掉指向不存在目录的**僵尸条目**（换名/重建会留下 `.staging` / `.old`）；
  2. 同一路径只保留**一条**记录；
  3. 身份三方对齐：内容 `id` == `Timelines/project.json.main_timeline_id` == 目录名；`meta.draft_id` == 索引 `draft_id`。

### 2. 注册流程：要求关剪映 → 支持剪映运行中

- **上游做法**：直接写目标目录，被占用就失败。
- **我们改成** `rebuild_draft.py` + `swap_draft.py` 两段式：
  1. 在**同级目录**构建 `<名字>.staging`（剪映不会碰它）；
  2. 落盘时检测目标目录句柄，被占用则 `--retry-free <秒>` 轮询；
  3. 释放后 `shutil.move` 换名，再补索引。
- **实测**：剪映停在**首页**时目录不带独占句柄，直接换名即可；停在**编辑页**才会占。
  ⇒ 人只需要「退到首页」，不用退出 App。

### 3. 内容镜像：1 份 → 4 份逐字节相同

- **上游做法**：写一份 `draft_content.json`。
- **剪映 11.6 要求**：根 `draft_content.json` · `Timelines/<uuid>/draft_content.json` · 根 `template-2.tmp` ·
  `Timelines/<uuid>/template-2.tmp` **四份 md5 必须相同**（加密一次，其余复制；分别加密会因 IV 不同而 md5 不同）。
- **我们改成**：加密一次 → 另外三处 `shutil.copyfile`；`Timelines/<uuid>/template.json` 再写一份**明文**快照。

### 4. 内容元信息：库默认值 → 对齐母版

- **问题**：上游按库默认写 `new_version = 143.0.0`、`platform` 为空。本机剪映 11.6 的母版是 `189.0.0` + 真实 platform 值。
- **我们改成**：从母版继承 `new_version` / `platform` / 时间线 `id`，避免版本自愈行为不可预期。

### 5. 素材箱：上游没有这个能力（自研）

剪映的素材箱要**三层齐备**：

| 层 | 字段 | 缺了 |
|---|---|---|
| 定义 | `content.materials.videos/audios/images`（含 `local_material_id`） | 缩略图空、时长 0 |
| 列表 | `draft_meta_info.draft_materials`（type 0 / 6 / 8） | **不显示** |
| 成员 | `draft_virtual_store.draft_virtual_store[type=1]` 的 `child_id` | **不显示** |

**实测铁证**：母版里有 9 条素材箱条目在 `content.materials` 里**根本没有定义**，照样显示
⇒ 列表念的是 `meta`，不是 `content`（网上流传的「meta 只是影子」是错的）。

`rebuild_draft.py` 的做法：**以母版为底，三层按 id 合并，只追加不删**
（老板口径：动复制出来的素材时，不能动草稿箱里的东西，完整保留）。

### 6. 交付体检：上游无（自研）

`audit_media.py` 一条命令查：素材路径存在性（并与母版对齐，母版缺的允许缺）、
`local_material_id` 覆盖率、`内容 ids ⊆ 树 child_ids ⊆ meta ids`、时间线是否被改动。

---

## 三、一句话结论

**加解密是上游的，能用「剪映开着也能操作」是我们在注册与落盘层重写的。**
上游解决「能不能解开草稿」，我们解决「解开之后怎么安全地写回去、还能被剪映认」。
